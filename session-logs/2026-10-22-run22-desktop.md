# 2026-10-22 — Run 22 (stability and creep first), desktop

All results are **simulator** results (MuJoCo, 2° slack unless noted). Nothing from
run 22 has been on the car.

**User's priorities:** stability and creep, then payload, then slope. Climbing slopes is
not trained yet (see the end of this log).

**Settings:** run 21 (payload 0–2 kg, PWM-step and wobble penalties gated near upright,
`osc`/`lean` inputs, `osc` penalty), plus:
1. **All calm penalties paused during a push and 1 s after.** Run 21 paused only the
   wobble penalty and eased off when shoved empty (2 N: 1/18).
2. **30 % stand-still commands** (`STAND_CMD_PROB`). A uniform draw almost never gave
   exactly 0.
3. **Position memory 8 s** (`POSITION_TAU_S`, was 2 s). The integral restarts from 0
   whenever the forward command changes, so it never "catches up" distance.
   **Firmware:** `POLICY_POS_DECAY` = 0.99937520 and the same reset rule in
   `policy.c` (`g_last_cmd_f`). `check_obs_builder` passes, including a run with the
   command changing every 20 ticks.
4. **A random floor slope of ±2° per episode** (`FLOOR_SLOPE_DEG`), by tilting gravity.
   The pitch input is made gravity-relative (`_sense()` subtracts the slope), as the
   car's IMU is.

**Run:** 30M steps, about 1 h 50 min.

**Files:**
- Checkpoints in `models/ckpt_run22/`
- Final in `models/ppo_real_robot_RUN22_30M.zip`
- Best-by-eval (30.0M) in `models/best_real_RUN22/`

## Verdict: 24M exported

- **Stability:** the calmest checkpoint of any run at 2° (4.0–5.4), with the fewest
  reversals. Empty 2 N push survival rose from 1/18 to 17/18.
- **Creep:** about 1 cm/s or less on ±2° floors, 3–4× better than run 21. It returns to
  within about 5 cm of its spot after a push; run 21 fell in that test.
- **Payload:** 0–4 kg standing and driving; 4 N pushes 18/18 with 2 kg.

**Weaker than run 21:**
- At 4° slack (a worse-geared car), 7.1–23.5 against 11.4–13.1. On the 2026-10-21 car,
  run 21 measured calmer than its 2° simulation, so that car is nearer 2°.
- **Empty 3 N pushes:** 0/18 in every run. The open gap against the PID's 17/18.

## Firmware

- `policy.h` `POLICY_POS_DECAY` is now exp(−dt / 8 s), and `policy.c` restarts the
  position integral when the forward command changes. **Run 22 needs both.**
- Run 21 needs the old 2 s decay and no reset rule.
- The change adds a float compare and a store. Only 48 B of flash were free for run 21,
  so check the build size.
