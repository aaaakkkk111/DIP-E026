# 2026-10-23 — Run 23 (full position memory), desktop

All results are **simulator** results (MuJoCo, 2° slack unless noted). Nothing from
run 23 has been on the car.

**Spec:** the laptop's, in `TRAINING_ON_DESKTOP.md` (2026-10-22). Remove the creep and the
load-dependent trim (1.7° empty, about 2.5° with 2 kg) the way the stock PID's speed integral
does: it never forgets, and it is clamped.

**Settings:** run 22, plus:
1. `POSITION_TAU_S = inf` (no leak). The ±0.5 m clip and the reset on a new forward command
   stay.
2. `POS_ERR_RANDOM_START`: training episodes start the integral uniformly within ±0.5 m, so
   the policy has seen the values a minutes-long car run reaches. It is off in
   `check_obs_builder.py` (the firmware starts at 0) and in evaluation.
3. **Firmware:** `POLICY_POS_DECAY 1.0f` in `policy.h`. A constant only, 0 B.

**Checks:**
- `check_obs_builder` could not run here: Windows Smart App Control blocked the freshly built
  DLL. The change is one constant, exact in both float32 and float64; the laptop's
  `check_obs_builder` run before flashing covers it.
- `test_policy`: PASS (worst 2.4e-2). The int16 check: MATCH.

**Run:** 30M steps, about 1 h 50 min.

**Files:**
- Checkpoints in `models/ckpt_run23/`
- Final in `models/ppo_real_robot_RUN23_30M.zip`
- Best-by-eval (25.5M) in `models/best_real_RUN23/`, **exported**

## Over training

- **Standing:** calm throughout. Empty was 1.5–1.9 deg/s at 13M, the lowest of any run.
- **Loaded:** the rise when payload training began at 15M was smaller than run 22's
  (12–15 against 41–50 deg/s).
- **Empty 2 N pushes:** 0/18 at 15M, 15/18 at 20M (run 22: 6/18), 16/18 at 25M.
- **The 10 s creep readings** in the 1M-step updates (+1 to +2 cm/s) are misleading for a full
  integral. A 60 s stand at 14M showed it drifts for about 10 s while the memory fills, then
  stops (−0.5 to +0.7 cm/s after 10 s). It settles a few cm from its start: the stored
  integral provides the lean that cancels the offset.

## Verdict: 25.5M exported

**Against the spec:**

| criterion | result |
|---|---|
| Creep smaller than run 22's | **yes**: it stops after about 30 s in every case, where run 22 keeps going |
| No bigger slow sway | **yes**: tilt sd the same as run 22's; up to 10–20 cm of motion while the memory fills |
| Wobble no worse | **yes, better**: 25.5M is the steadiest of any run at 4° (5.6–9.9) |
| Pushes no worse | **2 kg: yes** (18/18 at 4 N). **Empty 2 N: 13/18** against run 22's 17/18 (24M/25M: 16/18) |
| Starting from a full memory | **yes**: recovers without falling or running away |

**Why 25.5M over 24M/25M:** the steadiest on both a good and a worse car (slack varies day to
day) and the lowest creep. The price: empty 2 N pushes 13/18 and one 4 kg drive in 3 fell.
24M is the alternative if push recovery matters more.

**Car behaviour to expect:** if the car is pushed or carried far by hand while running, it drives
back up to 0.5 m to its original spot, like the stock PID. A new drive command clears the
memory.
