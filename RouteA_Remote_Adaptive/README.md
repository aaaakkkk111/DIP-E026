# RA3.0-SEQ1：RA3.0回滚与逐项PID更新

基于用户明确确认“未调参时能稳定”的RA3.0-REMOTE恢复控制。原始HEX单独保留；新版本恢复其PID计算、Normal/Load倍率和默认启动参数，只在调参路径增加单参数队列及通信安全处理。不是继续基于已放弃的RA3.3或RA3.2候选叠加。

## 模式

| 启动菜单 | 来源 | PID显示值 AP/AD/VP/VI/TP/TD |
|---|---|---|
|1.Standard Mode|原官方模式1，对照|96/48/62/31/17/20|
|2.Load Mode|原官方模式4，对照|96/75/70/35/14/20|
|3.TEST MODE|RA3.0 TEST，人工及LLM|初始96/48/62/31/17/20|

内部模式ID仍为0/3/20，菜单只映射成1/2/3；没有把内部逻辑ID改成0/1/2。其余功能模式、源码和Keil编译项已删除。保留MPU6050、编码器、电机、蓝牙、OLED、按键、电池、超声波距离等现有功能必需代码。TEST的N/L预设不改变物理菜单模式。

## 使用

1. 打开 `firmware/USER/stm32_Balance_Car.uvprojx`，或者直接烧录 `releases/stm32_Balance_Car_RA3.0_SEQ1.hex`。
2. 断电重启，确认只有1/2/3档。选择3.TEST，KEY1确认选模，再按KEY1启动控制。
3. 用Bluefy打开本次 `releases/index.html` 或 `routea_remote_adaptive_bluefy.html`。页面和回传版本均应为RA3.0-SEQ1。旧RA3.0/RA3.3网页和组员的P1页面不支持本次顺序写入。
4. 先确认自平衡，再在人工页修改AP96→95，点更新平衡环。只发AP一项；AD/速度环/转向环均不发送、不写入。成功需完成ACK及带事务ID/步骤号的实际PID读回。
5. TP17→18并点更新转向环，只发TP。保持17不变时不会发ONE，属于无修改操作。
6. 多项修改时，每项确认读回后等待1000ms，再发下一项。队列运行时禁止再次人工应用或启动另一轮训练。状态文字显示当前项和进度。
7. LLM仍从窗口数据提出N/L预设或PID候选，客户端使用完全相同的逐项发送队列；全部项及最终配置确认后才进入稳定期和两次评价，随后接受或回滚。绝对保护范围保留，没有新增相对百分比限制。
8. 超时、拒绝、读回不一致、停止或断连会终止剩余项并请求恢复序列开始前确认参数。活动事务仍有STM32心跳/TTL回滚。

## 边界

未调参时保持RA3.0控制行为；在线更新不清积分/滤波，也不执行RA3.1/3.2的500ms插值，不引入RA3.3启动PID内存锁停。为避免恢复已知收包风险，仍保留4KB栈、静态格式化缓冲和严格十进制解析，移除了浮点sscanf。原物理倾角、电池保护仍有效。逐项赋值并不保证任意最终参数或中间组合能稳定；风险回滚也不能保证已倾倒的车重新站起。

此轮尚未上车或调用真实LLM服务，不能把原生C/Mock通过当成实车已验证。组员参考网页实际为P1/T1、RA1.7版本，和RA3.0 P3/T3属于不同协议；其截图只能证明异常显示，不能单独证明本项目RA3.0的具体故障根因。
