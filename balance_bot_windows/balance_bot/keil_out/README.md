# 负载自动切档 —— 先看这个

小车能自己判断装没装货，切换两套 PID。空车用一套、装货用另一套。

**但用哪一套，取决于你这台车的电机死区。所以第一步是测死区，不是烧代码。**

---

### `db650soft/` 是干什么的

`db650/` 装上之后车能站住、但**振荡太大**，就换这个。差别只有一处：
NORMAL 档的 `Balance_Kp` 从 28800 降到 24000，HEAVY 档留在 28800。

**两档的 kp 本来就不该共用**，以前共用只是历史原因。扫下来约束是**单边**的
（电机死区 1450，8 种子）：

补偿 1500（`MOTOR_IGNORE_PULSE` 改过）：

| | N kp | H kp | NORMAL 0/1/2kg | HEAVY 2/3/4kg | 空车行程 | osc | 换向/秒 | 余量 |
|---|---|---|---|---|---|---|---|---|
| `db650/` | 288 | 288 | 7/8 8/8 8/8 | 8/8 8/8 1/8 | 139 mm | 43.0 | 1.4 | 1.77x |
| `db650soft/` | **240** | 288 | 8/8 8/8 8/8 | 8/8 8/8 1/8 | 120 mm | 43.2 | 1.3 | 1.77x |

补偿 1300（没改，原厂值）：

| | N kp | H kp | NORMAL 0/1/2kg | HEAVY 2/3/4kg | 空车行程 | osc | 余量 |
|---|---|---|---|---|---|---|---|
| `db650/` | 288 | 288 | **1/8** 8/8 0/8 | 8/8 1/8 0/8 | 276 mm | 64.4 | 1.91x |
| `db650soft/` | **240** | 288 | **7/8** 8/8 0/8 | 8/8 1/8 0/8 | 208 mm | 57.1 | 1.91x |

**如果你的 `MOTOR_IGNORE_PULSE` 还是 1300、而电机死区确实接近 1450，
下面那张表就是你现在的处境**：空车 1/8、行程 276 mm、osc 64 —— 这正是
「能站住但振荡太离谱」。降 kp 把空车从 1/8 拉到 7/8、行程砍掉 68 mm。

NORMAL 的 kp 一路降到 208 都不掉分；掉的是 HEAVY 的 3 kg（240 还是 6/6，
224 就 0/6）。所以 NORMAL 降、HEAVY 留住。

> **话说在前头：孪生量不出减 kp 在补偿 1500 那一侧的好处。** 低频晃
> 43.0 vs 43.2 mm；31 Hz 抖动在 208~288 这一段跟 kp 没有系统性关系
> （第一轮看着降了 35%，换种子重测不复现，那是噪声）。
>
> 选 240 的理由是「每一格都不比原来差，而且是你在真车上要的方向」，
> 不是「孪生说它更好」。**最终值要在真车上选** —— 孪生排不了「停振快慢」
> 这种暂态质量，实测上升时间差 3 倍、超调 0% vs 85%。用 `--tune`，见下节。

4 kg 那一列是 1/8：**db650 这一家做不了 4 kg**，那要 `db1500/` 的 kp 384。

`db650soft/` 的 `MOTOR_IGNORE_PULSE` **保持你跑 `db650/` 时用的那个值**。

## 定最终增益：`--tune`，不用再编译-烧录-复位

装好 `debug_uart/` 之后：

```
python scripts\capture_uart.py COM5 --tune
```

每格自动改增益 → 等 4 秒站定 → 收 20 秒遥测 → 打一张表：

```
   kp   vkp   vki |     rms     osc  rev/s |  倾角rms     峰值
  288    82  0.69 |   25.10    43.0   1.40 |    0.85度   2.31度
  240    82  0.69 |   21.30    39.0   1.30 |    0.81度   2.10度
```

- `rms` 26~46 Hz 陀螺能量 = 高频嗡嗡（也是自动切档的判据本身）
- `osc` 0.3~3 Hz 位置能量 = **低频前后晃**
- `rev` 每秒换向次数 = 「来回窜」有多勤

**「振荡太离谱」量的是 `osc` 和 `rev`，不是 `rms`。** `rms` 是 26~46 Hz 的
带通，一秒晃一次的车在那个频段上是平的 —— 只盯 `rms` 会把这个抱怨整个
漏掉。`osc`/`rev` 需要接上 `LD_Pos()`，见 `debug_uart/README_debug_uart.md`
里「选接」那一节。

把表贴回来就能定值。

> **在线调参以前是坏的。** `LD_Tick()` 每个 200 Hz tick 把六个增益从档位表
> 重写一遍，而旧的 `p/d/v/i` 命令写的是那几个全局量 —— 5 毫秒后就被盖掉，
> 命令回 `ok` 但车毫无反应。现在改成写档位表了。调参前先 `m 1` / `m 2`
> 锁住档位，否则检测器可能在你手底下切档。

## 强烈建议先装 `debug_uart/`

它把每一步从「改代码 → 编译 → 烧录 → 复位」变成「敲一行命令」，
接线只要三处各一行。标定、锁档位试增益、录数据都靠它。

而且它能帮你排掉一个**上车前唯一能提前排掉的重大风险**：本方案的带通
选在 26.5–45.5 Hz，依据是**孪生里**空车抖动主频 31 Hz。真车主频没人量过，
如果不在这个区间，检测器直接失效。录 30 秒数据跑个 FFT 就知道。

详见 `debug_uart/README_debug_uart.md`。

## 什么是死区，为什么要测

给电机一点点电，它**不转** —— 静摩擦和齿轮间隙顶着。加到某个值才突然开始转。
那个值就是死区。

原厂代码知道这回事，所以每次输出都硬加 1300（`APP/app_motor.c`）：

```c
#define MOTOR_IGNORE_PULSE (1300)//死区  1450 25Khz   此值需要看静止状态微调
int PWM_Ignore(int pulse)
{
    if (pulse > 0) return pulse + 1300;
    if (pulse < 0) return pulse - 1300;
    return pulse;
}
```

意思是「1300 以下电机反正不动，我先垫上，剩下的才是真正的控制量」。

**问题是 1300 只是个默认值。** 厂家注释自己写着「此值需要看静止状态微调」，
而全套 20 多个例程用的都是这同一个数，没有一台车标定过。

- 你的车实际是 **700** → 垫 1300 多垫了 600，电机一有输出就猛窜 → **抖**
- 你的车实际是 **1700** → 垫 1300 还差 400，小指令电机不动 → **迟钝、起步往前扑**

PID 该配多大，直接取决于这个数。

## 怎么测（约 20 分钟）

### 1. 车架起来，两个轮子悬空

书本垫住底盘就行。轮子必须能自由转。

### 2. 关掉死区补偿

`APP/app_motor.c` 第 5 行：

```c
#define MOTOR_IGNORE_PULSE (0)      /* 原来是 1300 */
```

### 3. 加测试代码

把 `deadband_test/` 里的两个文件加进工程（Keil 右键 `APP` 组 →
Add Existing Files）。

`USER/main.c` 顶部：

```c
#include "deadband_test.h"
```

`while(1)` 里面，**最前面**：

```c
while(1)
{
    DB_Test();
    while (1) { }        /* 停在这，不跑平衡环 */

    /* ... 原来的代码留着别删 ... */
}
```

### 4. 烧进去，盯着轮子

PWM 从 0 开始，每 0.5 秒加 25。**记下轮子刚开始转的那一刻**。

读数有两个办法：
- Keil 在线调试，Watch 窗口加 `db_pwm`
- 接了串口就自己加 `printf`

### 5. 左右轮分开看

两个轮子很可能不一样。**如果一个先转一个后转，记后转的那个**（大的）。

## 测完之后

### 死区 ≤ 1400

1. `MOTOR_IGNORE_PULSE` 改回 **1300**
2. 删掉 `main.c` 里那两行 `DB_Test(); while(1){}`
3. 把 `deadband_test.c` 从工程移出
4. 按上面的表选目录，加它的 `load_ctrl.c` / `load_ctrl.h`
5. 按那个目录里的 `load_ctrl_README.md` 接线

### 死区 1400–1700

用 **`db1500/`**，并且**必须**把 `MOTOR_IGNORE_PULSE` 改成 **1500**。

有意思的是：补偿量改对之后，PID 和 `db1300/` **一模一样**——死区被补偿完全
吸收了，增益不用动。变的只有两个检测阈值（31 Hz 模态的幅值跟着死区变）。

实测（死区 1500 + 补偿 1500，8 种子，0/1/2/3/4 kg）：

```
NORMAL   7/8  8/8  7/8  4/8  0/8
HEAVY    7/8  8/8  8/8  8/8  8/8
```

NORMAL 在 3–4 kg 掉下去是设计如此，那时检测器已经切到 HEAVY 了。

kp 在 384–416 是一片高地（4 kg 下都是 8/8），352 和 448 降到 6/8。取 384。

### 死区 > 1700

**先把 `MOTOR_IGNORE_PULSE` 改成你实测的值**，然后用 `db1500/`。

这一步不能省。死区超过补偿量之后，**调 PID 救不回来** —— 实测死区 1700 时，
`Balance_Kp` 从 9600 到 38400 全部试过，没有一个能让车站住（0/8）。

原因是垫少了，小指令电机不动，控制环等于断了，这不是增益大小的问题。
把补偿量改成 1700（垫够），立刻从 0/8 变成 5/6。

## 嫌麻烦，不想测

直接用 **`db1300/`**，其他什么都不改。那是对应厂家默认假设的版本。

不合适的话现象很明显：

| 现象 | 说明 | 怎么办 |
|---|---|---|
| 高频嗡嗡响、车抖 | 你的死区比 1300 小 | 换 `db650/` |
| 迟钝、起步迈不开、容易往前扑 | 你的死区比 1300 大 | 回去测 |

代价是拿车试错，而不是 20 分钟测准。

PID 增益会变成随机数。烧完读回 `Balance_Kp`，对一下是不是表里那个数。
